# アイスボーン装備さがし（非公式）

モンスターハンターワールド：アイスボーンの装備を探すページです。「作りたい装備」の条件を入れると、防具 5 部位・護石・装飾品まで含めた組み合わせを、順位を付けて複数出します。サーバーはいりません。`dist/index.html` という 1 つのファイルに、データも計算のプログラムも全部入っています。

これは非公式のファンツールです。ゲームのデータと画像の権利は株式会社カプコンにあります。装備を作る前に、必ずゲームの中で確かめてください。

## 使い方

- `dist/index.html` をブラウザで開きます。スマホでも使えます。
- 「条件で探す」：武器・ほしいスキルとレベル・目的（火力、守りとの両立、守り、快適さ）・ランクを選んで「探す」を押します。くわしい条件では、外せない防具、使わない防具、持っていない装飾品、防御力や耐性の下限、レア度の上限（入手しやすさ）、探す時間を決められます。
- 「作っておいた案」：14 種類の武器 × 3 つの目的で、あらかじめ検索しておいた案を見られます。
- 「言葉で頼む」：Claude の Artifact（Claude の中で公開されたページ）として開いたときだけ出ます。「太刀で火力重視、見切りと超会心は外したくない。弱点特効は 3 以上」のように書くと、Claude が検索条件に直して、ページの検索結果から順位と理由を決めます。

### 友達への渡し方

- GitHub Pages（GitHub の無料の公開場所）で公開した URL を送ります。公開のしかたは下の「公開のしかた」にあります。
- 案ごとの「この案の URL をコピー」を押すと、その案だけを開ける URL ができます。友達がその URL を開くと、ページの一番上に同じ案が出ます。
- 「一覧をコピー」を押すと、ゲームの中で確かめやすい文字の一覧（武器、各部位、差す装飾品、護石、発動スキル）がコピーされます。

## データ

使っているのは GitHub の `gatheringhallstudios/MHWorldData` だけです。commit `be7362213d7d1e30b794e3b58d3f87712035658d`（2021-03-04、Fatalis update）に固定しています。プログラムのライセンスは MIT、データの権利はカプコンにあります。

- `tools/fetch_data.sh`：固定の commit から、必要な CSV だけを `data/source/` に写します（git の取得だけを使い、ほかのファイルは読みません）。
- `tools/build_data.py`：CSV から `data/game.json`（ページで使うデータ）と `data/report.json`（行数や見つからなかった名前の記録）を作り直します。
- 画面の名前は `name_ja` の列の日本語名です。

## 守っているルール

- スキルごとの上限。極意スキル（例：挑戦者・極意）が付くと、上限が上がります。上限は `skill_levels.csv` の行の数から、`skill_base.csv` の `secret` の数を引いて求めています。
- シリーズスキルの必要部位数（`armorset_bonus_base.csv`）。
- 装飾品の大きさは、差すスロットの大きさ以下。大きさ 4 の複合の装飾品（2 つのスキルが付くもの）も扱います。
- 護石は 1 つ。`previous_en` を持つ護石は、選んだランクとレア度の中で一番上の段階だけを候補にします（例：攻撃の護石は最終段階）。

## 点数の付け方（判断と理由）

順位は、作者（Claude）が決めた式で計算しています。攻略サイトや、ほかの装備シミュレーターは見ていません。ページの「点数の付け方」に同じ説明と、すべての数があります。

- 案ごとに「火力点」「守り点」「快適点」を計算し、目的に合わせて足します。「守りとの両立」は 火力点 ＋ 守り点 × 0.5 です。体力増強 Lv3 と攻撃 Lv3 がだいたい同じくらいの重みになるように決めました。
- 火力点は、スキルなしの期待値を 100 とした値です。物理期待値（基礎攻撃力と会心から出す、平均で出るダメージの目安）と属性期待値を足しています。スキルの数値（攻撃力＋3、会心率＋5% など）は、すべて `skill_levels.csv` の日本語の説明文から読み取りました。数値が読めないスキルは点数に入れず、案ごとに「数値に入れていないスキル」として表示します。
- 「発動中」などの条件があるスキル（挑戦者、フルチャージ、渾身など）は、効果に割合をかけて数えます。割合は、スキルの説明文に書かれた条件（怒っている間、体力が最大のとき、など）を読んで作者が決めました。火事場力は「体力が 35% 以下のとき」なので、狙わない前提で 0 にしました。画面で全体を 0 倍から 1.5 倍に変えられます。
- 守り点は、防御力（防具の強化を最大にした値）、耐性の合計、体力の増加、生存スキル（耳栓・回復速度など）のレベル、ダメージ軽減から出します。
- 快適点は、余るスロット（大きいほど高い点）と便利スキル（回避距離・高速設置など）のレベルから出します。
- 似た案ばかりにならないよう、防具が 2 部位以上違う案を先に並べます。

### データにない前提の数

データにない数は、なるべく使わないようにしましたが、次の 4 つだけは置く必要がありました。

1. 会心の基本倍率 1.25：超会心 Lv1（1.3 倍）と Lv2（1.35 倍）の差を、Lv1 から引いて求めました。データからの推定です。
2. マイナス会心で減る割合 0.25：データにありません。作者が置いた前提です。
3. 属性値を 10 で割って物理と足すこと：作者の判断です。
4. 武器倍率（表示攻撃力を基礎攻撃力に直す数。太刀 3.3、大剣 4.8 など）：スキルの「基礎攻撃力＋3」と単位を合わせるために必要です。データの表示攻撃力をすべて割り切れる数を調べると候補が複数あり、データだけでは一つに決まりませんでした。そこで、割り切れる候補の中から、作者が知っている値を選びました。これは記憶による数なので、判断してほしい点として最後の報告にも書きました。

## 探し方（判断と理由）

全部の組み合わせは数億通りになり、ブラウザの中では間に合わないため、次の方法で減らしています。条件を満たす案を取りこぼさないことを優先しました。

- 支配される防具を外す：同じ部位で、ほかの防具よりスキル・スロット・防御のどれも上回らない防具は、使っても一番良い案は変わらないので外します。
- 装飾品で置きかえられる防具を外す：ほかの防具のスロットに装飾品を差すとそのスキルを作れて、しかも同じ大きさ以上のスロットが残るなら外します。
- 少しずつ広げる探索：候補を良さそうな順に並べ、各部位の上位 2 個、3 個、4 個…と広げながら調べます。早い段階で良い案が見つかります。
- 枝刈り（見込みのない枝を切ること）：「この先どう選んでも条件を満たせない」「この先どう選んでもいまの上位の点数に届かない」とわかったら、その先は調べません。
- 時間切れ：決めた時間で止めて、そのことと、何段まで調べたかを画面に出します。最後の段まで終われば、全部を調べたのと同じ結果になります。
- 画面が止まらないよう、計算は Web Worker（画面とは別に裏で計算するしくみ）で行います。使えない環境では、少しずつ計算して、そのたびに画面へ戻ります。

## 言葉で頼む入り口（Claude）

- Claude の Artifact として開いたとき、`window.claude` の `claude.use("sample")` を使います。公開するときの宣言は `capabilities: {sample: {}}` です。
- 呼ぶときは `model: "claude-opus-5-5"` を指定します。答えの `modelApplied` が `claude-opus-5-5` でないときは、別のモデル（`modelTierApplied` の段階）が答えたことを画面に出します。
- Claude には、ページの中の関数を道具（tools）として渡します。`findSkills`（スキル名を探す）、`findWeapons`（武器を探す）、`searchBuilds`（条件で検索する）、`getBuild`（案の中身を見る）です。道具の答えは 32KB 以内にしています。
- 装備名と数値は、Claude の文章ではなくページのデータから表示します。Claude の答えの `buildId` が検索結果にないときは表示しません。
- `claude.use("sample")` が `null`（GitHub Pages など）のときや、`not_granted`（使う許可がない）のときは、この入り口を隠し、作っておいた案と条件検索に案内します。
- 呼び出しはボタンを押したときだけで、自動で繰り返し呼びません。使われるのは、ページを見ている人の Claude の利用枠です。

## 作っておいた案

`tools/make_presets.js` が、14 種類の武器 × 3 つの目的（火力、守りとの両立、快適さ）× 2 つの入手しやすさで、検索プログラムを 1 回 30 秒ずつ実際に動かしました。各目的に、入手が難しい装備も使う案を 3 つ、入手しやすい案を 2 つ入れています（合わせて 210 案）。理由の文は `tools/finish_presets.js` が、検索プログラムが計算した数だけを使って組み立てます。

- 入手が難しい装備も使う案：レア度 12 まで、全部使います。武器は、条件の中で「スキルなしの期待値」が一番高いものです。
- 入手しやすい案：武器・防具・護石・装飾品のレア度を 10 以下にしました（レア度が高いほど手に入れにくい、という判断です）。
- ランス・ガンランスの「守りとの両立」だけは、ガード性能 Lv3 を必ず付ける条件にしました（ガードで受ける武器のため）。ほかは、外せないスキルを決めず、点数だけで選んでいます。

## 確かめ方

```bash
node tests/run.js
```

- 検索プログラムとは別に書いた採点プログラム（`tests/checker.js`）で、すべての案のスキル・スロット・シリーズスキルを計算し直し、一致を確かめます。作っておいた案は全部確かめます。
- 小さな例（各部位 4 個・護石 4 個）で総当たりと比べ、一番良い案を取りこぼさないことを確かめます（24 例）。

```bash
node tests/browser.js
```

- ヘッドレスのブラウザ（画面を出さないブラウザ）で `dist/index.html` を開き、パソコンの幅とスマホの幅（375px）で、条件検索・URL での共有・コピー・作っておいた案が動くことと、コンソールにエラーが出ないことを確かめます。
- `window.claude` をまねたもので、言葉で頼む入り口の動き（隠れる・断られる・道具を使って答える）を確かめます。本物の Claude の画面では試していません。

## 公開のしかた（GitHub Pages）

`.github/workflows/pages.yml` に、main に入ったら `dist/` を公開する設定を入れてあります。最初の 1 回だけ、次の手作業が必要です。

1. GitHub でこのリポジトリを開き、上の「Settings」（設定）を押します。
2. 左の一覧の「Pages」を押します。
3. 「Build and deployment」の「Source」で「GitHub Actions」を選びます。
4. pull request を main に入れる（Merge する）と、数分で公開されます。公開先は「Pages」の画面の上に出ます（ふつうは `https://majikichi700-oss.github.io/mhw-build-sim/` です）。
5. リポジトリが非公開（Private）の場合、無料のプランでは Pages を使えないことがあります。そのときはリポジトリを公開（Public）にするか、Artifact で共有してください。

## 対応していないこと

- 防具と武器のカスタム強化、覚醒武器の覚醒能力（データに中身がないため）。
- 斬れ味、モーション値（技ごとの威力）、肉質（部位ごとの効きやすさ）、属性値の上限、弾やビン、狩猟笛の旋律、猟虫。
- 説明文に数値がないスキルの火力（会心撃【属性】、無属性強化など）。不屈と抜刀術【技】は火力点に数えません。
- 装飾品を持っている個数（「持っていない」の指定だけできます）。
- 重ね着、モンスターごとの弱点。
